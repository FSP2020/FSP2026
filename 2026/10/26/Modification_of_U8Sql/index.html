会计系统基本原理

摘要

  在《会计信息系统》课程实训中，U8 账套依托 SQL Server 存储全部业务与日志数据。本文通过实操 SQL 语句，学习账套数据查询、复制与修改的底层操作，观察表之间关联关系，理解业务界面和数据库底层的数据映射逻辑，以此加深对数据库增删改查、事务、表结构的理解。本内容仅作为数据库技术学习资料。

关键词

U8v15; SQL 2008R Enterpise ;VMware Workstation Pro 17.5

SQL Server Management Studio 基础入门

  SQL Server Management Studio，简称 SSMS，是微软官方提供的可视化数据库管理工具，用来连接、管理 SQL Server 数据库实例。U8 的账套业务数据、上机日志、凭证信息全部保存在 SQL Server 数据库中，我们就是通过 SSMS 连接后台数据库，执行 SQL 语句，完成数据查询、复制等实操练习。

在SSMS中定位账套

  完成登录后，在左侧【对象资源管理器】展开数据库节点。
U8数据库有固定命名规则：

  • UFMeta_账套号：账套元数据库，存储账套基础配置信息
  • UFDATA_账套号_年度：业务数据库，凭证、单据、上机日志等业务数据均存放于此
  • UFSystem：U8全局系统库，统一管理全部账套、操作员、权限信息

UA_User（操作员表）

存放库：UFSystem（系统库，不是业务UFDATA库），保存U8所有操作员账号、状态、账套主管标记。

  • 常用字段
    • cUser_Id：操作员编码（登录账号）
    • cUser_Name：操作员姓名
    • cPassword：加密后的登录密码（不能直接明文改）
    • iAdmin：是否账套主管，1=是，0=否
    • nState：账号停用标记，0=启用，1=停用

注:若需要设置空密码，需令cpassword= ‘2jmj7l5rSw0yVb/vlWAYkK/YBwk=’
U8采用了哈希加密手段，若使用未加密的字符串，会导致账套无法登录

账套ID修改（修改备份lst导入法）

  原理：U8的账套备份会生成 UfErpAct.Lst，这个文本文件里面记录了账套号、账套名称、年度等信息，修改里面的账套标识，再执行账套引入，就能以新账套号恢复。

步骤

  1. 正常在U8系统管理，对目标账套做【账套备份】，备份完成后，找到备份文件夹。
    文件夹内一般有两个文件：UfErpAct.Lst + 数据库备份文件 .BA_
  2. 复制一份原备份整个文件夹做备份，右键 UfErpAct.Lst，用记事本/VS Code打开。
  3. 修改里面所有和账套号相关的参数
    示例原始内容（账套001，改成002）：

  • cAcc_Id：账套号（核心，把旧账套号改成你想要的新账套号）
  1. 保存 UfErpAct.Lst，关闭编辑器。
  2. 打开U8【系统管理】，admin登录，点击【账套】→【引入】，选中这个修改后的 UfErpAct.Lst，按照向导下一步导入。
    导入成功后，就是新账套ID的账套。

常见踩坑

  1. 编码问题：lst是ANSI编码，不要直接保存成UTF-8，会引入报错、引入失败。记事本保存时编码选 ANSI。
  2. 账套号重复：目标新账套号不能在当前数据库已经存在，否则引入报错。
  3. 年度账备份的lst和普通账套备份lst格式不一样，这个教程只适用于【账套备份】，不是年度账备份。
    为什么不直接数据库update改账套ID
    账套ID在UFSystem、各个UFDATA_xxx_年度几十张表都存在外键关联，直接SQL更新很容易出现档案、单据、权限错乱，后续查账、结账报错，极难修复。

总结

  本篇笔记整理了 U8 数据库相关的实操方法，包含数据库区分、底层数据修改、备份文件调整、文档排版与内部锚点等内容，仅作为个人技术学习、研究参考使用。U8 整套系统数据表之间存在大量隐藏关联、外键约束与业务校验逻辑，很多数据异常不会在操作完成的瞬间体现，常常延迟到凭证记账、月末结账、报表查询、年度结转的时候才暴露故障，排查难度极大，修复成本很高。
在有真实业务数据的生产环境中，优先使用 U8 前台界面、系统管理自带功能完成账套维护工作，尽量避免直接操作数据库、修改备份 Lst 文件这类绕过上层业务校验的手段。如果出于调试目的必须进行底层改动，一定要提前对整套账套做完整备份，并且单独留存一份备份文件，操作结束后逐项核对凭证、单据、余额表等核心数据，确认业务逻辑没有异常
